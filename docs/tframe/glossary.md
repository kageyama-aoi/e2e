# T-Frame テスト用語集

テストコードをあまり書いたことがない人向けの用語集です。

この文書では、

- 短く端的な説明
- どう理解すると分かりやすいか

の両方を入れています。

---

## まず押さえる用語

### テスト
アプリが期待どおりに動くかを確認する処理です。

理解の助け:
「人が目で確認していた作業を、コードで自動化したもの」と考えると分かりやすいです。

### シナリオ
1つの流れとしてまとめたテストです。

理解の助け:
「ログインして、メニューを押して、画面が開くまでを見る」など、ひとまとまりの手順です。

### Feature
似たテストをまとめる名前です。

理解の助け:
テストの見出しです。実行順を決めるものではなく、「何を試す集まりか」を表します。

### Scenario
1本の具体的なテストケースです。

理解の助け:
Feature の中に入る1つ1つの実行単位です。1 Scenario = 1 フロー、と覚えるとよいです。

### Assertion / Assert
結果が正しいかを確認することです。

理解の助け:
「できたかどうかを最後に判定するチェック」です。期待どおりでなければテストは失敗します。

## 画面操作まわり

### Page Object
画面操作をまとめたクラスのようなものです。

理解の助け:
テストの中に細かいクリック処理を書かず、「この画面でできる操作」をひとまとめにした部品です。

### メソッド
Page Object の中にある操作単位です。

理解の助け:
`login()` や `clickEmailIcon()` のような、名前付きの「やること」です。

### Locator / セレクタ
画面上の要素を見つけるための指定です。

理解の助け:
「このボタン」「この入力欄」を指す住所のようなものです。`input[id="loginmodel-username"]` のように書きます。

### クリック
画面上のボタンやリンクを押す操作です。

理解の助け:
実際に人がマウスで押すのと同じ意味です。

### 入力
テキストボックスに文字を入れる操作です。

理解の助け:
ログインIDやパスワードを入力する場面で使います。

### 遷移
別の画面へ移ることです。

理解の助け:
「メニューを押したら一覧画面に移った」など、画面が変わることを指します。

### URL
今見ているページの住所です。

理解の助け:
遷移先が合っているかを確認するための目印になります。

### スクリーンショット
画面の画像を保存することです。

理解の助け:
失敗時の証拠や、確認結果の記録として使います。

### 検証
画面や URL が期待どおりかを確認することです。

理解の助け:
「押した先が正しいか」「表示があるか」を見る作業です。

## CodeceptJS / Playwright まわり

### CodeceptJS
テストを書くための枠組みです。

理解の助け:
「テストをどう組み立てるか」を決める土台です。`Feature` や `Scenario` はここで使います。

### Playwright
実際にブラウザを操作するための仕組みです。

理解の助け:
ボタンを押す、文字を入れる、ページを開くなどの動きを担当します。

### `I`
テストで使う操作役です。

理解の助け:
`I.click()`、`I.waitForElement()` のように書いて、ブラウザ操作を行います。

### `inject()`
Page Object の中で `I` を受け取る仕組みです。

理解の助け:
「この画面操作用の道具を使えるようにする受け取り口」です。

### Suite
テストのまとまりです。

理解の助け:
`tests/tframe/*_test.js` をまとめて実行する単位です。

### Helper
補助的な共通機能です。

理解の助け:
本体のテストではなく、よく使う便利処理を支える役です。

### Plugin
追加機能です。

理解の助け:
Allure レポートや自動ログインのように、標準動作に足す仕組みです。

## T-Frame 特有の設定

### プロファイル
実行環境の種類です。

理解の助け:
`tframe` や `shimamura` のように、対象システムごとの設定を切り替えるために使います。

### `.env`
環境変数を置く設定ファイルです。

理解の助け:
URL、ID、パスワード、画面サイズなど、実行時に変わる情報を入れます。

### `PROFILE`
どの環境設定を使うかを決める変数です。

理解の助け:
`env/.env.tframe` のようなファイルを選ぶためのスイッチです。

### `LOGIN_TFRAME_URL`
T-Frame のログイン画面 URL です。

理解の助け:
最初に開く画面の住所です。

### `TFRAME_LANGUAGE`
画面の言語を指定する変数です。

理解の助け:
日本語 / 英語でメニュー名が変わるときに使います。

### `ADMIN_USER` / `ADMIN_PASSWORD`
管理者ログイン用の認証情報です。

理解の助け:
テストが「管理者として操作する」ために使う値です。

### `secret()`
秘密情報をログで隠すための仕組みです。

理解の助け:
パスワードやトークンをそのまま表示しないようにする安全装置です。

## ファイル構成で出る用語

### `tests/tframe`
テストシナリオを置く場所です。

理解の助け:
「何を確認するか」を書く場所です。

### `pages/tframe`
Page Object を置く場所です。

理解の助け:
「どう操作するか」を書く場所です。

### `data/tframe`
テストで使うデータを置く場所です。

理解の助け:
メニュー名や URL の一覧など、繰り返し使う情報を置きます。

### `codecept.conf.js`
テスト全体の設定ファイルです。

理解の助け:
「どのテストを動かすか」「どの画面サイズにするか」「どの Page Object を使えるか」を決めます。

### `support/envLoader.js`
環境変数を読む共通処理です。

理解の助け:
実行前に必要な設定を読み込む入口です。

## よく混同しやすいもの

### テストと Page Object
テストは流れを書く場所、Page Object は操作を書く場所です。

理解の助け:
テストは「何を試すか」、Page Object は「どうやって試すか」です。

### セレクタと URL
セレクタは画面上の要素を探す住所、URL はページの住所です。

理解の助け:
ボタンを見つけるのがセレクタ、遷移先を確かめるのが URL です。

### 検証と操作
操作は押す・入力すること、検証は正しいか確認することです。

理解の助け:
「やること」と「確かめること」は分けて考えると整理しやすいです。

---

## ひとことで覚える版

- テスト: 正しさを確認する
- シナリオ: 1つの流れ
- Page Object: 画面操作の部品
- セレクタ: 要素の住所
- Assertion: 正しいかの判定
- プロファイル: 実行環境の切り替え
- `.env`: 実行時設定
- `secret()`: 秘密情報を隠す
