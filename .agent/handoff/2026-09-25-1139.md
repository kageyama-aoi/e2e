## 試したこと・結果

### 成功したアプローチ
- **画面を開いて実フォームを `FormData` ごと POST**。既定値・hidden・CSRF を取りこぼさない。成否は `res.ok` ではなく URL の `record=` で判定。失敗時はエラー枠→本文→（本文なしなら）応答 HTML 先頭を例外に載せる
- **AJAX で作り直されるプルダウン（エリア→店舗）**: 項目を画面の上から順に入れ、select ごとに `change` を発火、選択肢が現れるまで最大 10 秒待つ、送信直前に値が残っているか再確認。`fields` は上から順に書く
- **チェックボックス**: `youbi_32: true` のように true で渡す（value 属性なしなら "on" が送られる）
- **編集画面**（CSRF 付き GET で開く）は「編集」ボタンだけ押し、`path` を省略して今の画面のフォームを送る
- **候補生を使わない確認**: 問合せ登録で使い捨ての受講生を作って編集→値を読み返す→UUID 指定で削除
- **UI と同じ操作でも同じエラーになるか**を比べると、フォーム送信版の問題か、データ側の問題かを切り分けられた
- 発表会セットアップを部分実行するときは `output/happyoukai_session.json` を退避→復元（BeforeSuite がリセットするため）
- /js-review で「両方読めないと `(読めず) === (読めず)` で素通り」を検出・修正（#232 と同じ種類の偽合格）

### 失敗したアプローチ（理由）
- **使い捨て受講生を銀行引落に変える** → 「銀行情報を入力してください」で保存不可（UI でも同じ）。【銀行情報】9 項目のうち **引落開始充当年月（`hikiotoshi_startdate`）が空** なのが原因とユーザー指摘・推定（未検証）。確認ランナーは現金のまま据え置いた
- **銀行名・支店名を送らない** → 空のまま。コードの**キー入力**で AJAX が埋める読み取り専用項目なので、フォーム送信では名称も直接渡す必要がある（共通部品の制約）
- **日本語の `--grep`（`"@dev | 銀行引落_スクール"`）で 1 行だけ実行** → Bash→Windows の node で文字化けし、絞り込みが効かず**全 10 行が走って候補生を 10 人消費**。同じコマンドの `--override`（scratchpad の通信記録プラグイン `netlog_plugin.js`）も読み込まれず記録ゼロ
- **TaskStop で停止** → シェルのラッパーだけ止まり、codeceptjs の node プロセスは動き続けた。最終行が経理処理中だったので最後まで流した
- sed で `\s` を含む行を置換 → GNU sed が `\s` を空白と解釈して行を壊した。Edit ツールで直した
