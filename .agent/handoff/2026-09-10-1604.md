## 試したこと・結果

### 成功
- **実機採取スクリプトは書かず、Claude in Chrome で直接 DOM 走査**（`#sideBar li.dropdown` を辿る JS）。プランC（手動→必要ならスクリプト化）で合意済み。
- 一覧検索テストの標準パターン（`/tframe-ichiran-dev` ＋ `IchiranMixin`）に、経理・Eメール系の2つのクセを吸収する層を追加：
  1. **日付レンジ既定が「当月」** → CSV に `dateFrom`/`dateTo`、`IchiranSearchMixin.setDateField()` で直接セット
  2. **エリア/対象区分/ステイタス等がサーバー側にセッション記憶** → `IchiranSearchMixin.resetSelects()` で「すべて」に戻す
  3. **エリア→校舎はAJAX連動** → 「エリアをリセット → `I.wait(1)` → 校舎をリセット」の順にする（`resetStickyFilters` 内）
  4. `IchiranMixin.verifyResultsExist` は thead 行にマッチし空振り判定できない → `IchiranSearchMixin.verifyResultRowsExist()`（tbody 実データ行数を assert、最大15秒ポーリング）を新設

### 失敗・ハマり（#199）
- Eメール一覧の絞り込みが3回落ちた。原因は積み重なっていた：
  1. 校舎リセットがAJAXレースで効かず「東京」が残る → area→wait→branch 順で解決
  2. `verifyResultRowsExist` がAJAX描画完了前に判定 → ポーリング化
  3. **根本原因**: テストは `env/.env.tframe.*` の `ADMIN_USER=adminuser` でログインするが、**`adminuser` は東京校舎スコープのデータしか見えない**。実機調査で使った Claude in Chrome セッションは別アカウント `beta_kage`（全データ可視）だったため、「渡辺」（景山横浜校舎のメール）で検証してしまい 0 件。→ 絞り込み値を「田中」（東京校舎にデータあり）に変更して解決。
  - **教訓**: tframe テストの検証値は `adminuser` の可視範囲で選ぶこと。Claude in Chrome の手動調査は `beta_kage` なのでスコープが違う。
