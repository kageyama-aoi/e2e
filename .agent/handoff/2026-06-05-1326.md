## 試したこと・結果

### 成功したアプローチ
- **フロー順序変更**：最初「編集→保存→smbc_button」の順を提案したが、ユーザー指摘で「先に債権買取顧客情報登録→後で請求方法変更」が正しい業務順序と判明
- **SMBCフォームへのナビゲーション確定**：
  - `?detailview=1&module=Student&action=DetailView` の URL でのみ `input[name="smbc_button"]` が表示される
  - `DW_AN` や `DWCarteKeiri_AN` には smbc_button なし
  - 検索→DW_AN→URLからrecordID抽出→DetailViewに直接遷移、というパターンで到達
- **SMBCフォームフィールド完全把握**：
  - readonly（受講生レコードから引用）: `gender`, `primary_address_*`, `bank_*`, `keiyakusha_*`
  - editable: `phone_mobile`, `last_name_furigana`, `first_name_furigana`, `gengo/year/month/day`, `area_id/school_id`, `primary_address_state_kana/city_kana`, `primary_address_street_kana`（textarea）
  - `keiyakusha_honnin_def=1` でkeiyakushaフィールドをeditable化できる
- **受講生基本情報の事前入力**：SMBCフォームのreadonly項目が受講生レコードから引用されるため、先に学生編集で gender/phone/address を設定する手順が機能
- **既存銀行情報の活用**：student_edit.html に bank_code=0005 が既存値として入っており、CSV を空にして再入力しないことで「銀行情報を入力してください」エラーを回避
- **Street/kana フィールド**：`primary_address_street` と `primary_address_street_kana` は `textarea`（input ではない）。JS で readonly を解除して設定

### 失敗したアプローチ（理由）
- 最初の順序（編集→保存→smbc_button）→ 「債権買取顧客情報が未登録のため選択できません」エラーで保存失敗
- `input[value="〒"]` 見つからずに `#zipCodeBtn`（tframe用）を使用 → shimamura は `input[value="〒"]` が正解
- bank_code=0001（架空）→「銀行情報を入力してください」。既存の 0005 を使うべきだった
- 銀行フィールドを CSV に指定して再入力 → AJAX が銀行名クリアして保存失敗。CSV を空にすることで解消
- `primary_address_street` を `input` として fillField → `textarea` のため ElementNotFound
- `primary_address_street_kana` も同様に `textarea`
- SMBC フォームの `gender` を selectOption（readonly でも値は変わる）→ ユーザー指摘で受講生レコード側で設定すべきと判明
