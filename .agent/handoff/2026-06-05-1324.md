## 試したこと・結果

### 成功したアプローチ
- `shimamura-html-fetch` スキルで `student_detail.html`・`student_edit.html`・`student_smbc_detail.html` を取得し、フィールド名を特定
  - 会員番号フィールド: `input[name="idnumber"]`（`acsno` ではなく `idnumber` が正解）
  - 編集ボタン: `input[name="edit_button"]`（DW_ANおよびDetailViewどちらでも同じ）
  - 債権買取顧客情報登録ボタン: `input[name="smbc_button"]`（`action=DetailView&detailview=1` の画面のみ表示）
  - SMBCフォーム保存ボタン: `input[name="save_button"]`（value=`申込情報登録`）
- `detailview=1` パラメータを付与した URL (`?detailview=1&module=Student&action=DetailView&record=...`) を使うことで `smbc_button` が表示される画面に到達
- 受講生検索→DW_ANへ着地→URLからrecordID抽出→DetailViewへ切替、というナビゲーションパターンが機能
- 先に受講生基本情報（性別・電話・住所）を student edit (EW_AN) で登録してからSMBCフォームを開く手順が有効
- SMBCフォームの `keiyakusha_honnin_def=1`（契約者あり）を選択してkeiyakushaフィールドをeditable化し、直接入力
- 銀行情報（bank_code=0005等）はすでに student record に設定済みのため、CSV で空にして既存値を維持する方法が機能

### 失敗したアプローチ（理由）
- `input[name="idnumber"]` を `acsno` と仮定 → 実際は `idnumber`（検索フォームの会員番号フィールド）
- 編集後の save で `return_action=DWCarteKeiri_AN` に戻ると `smbc_button` がない → `DetailView` から編集する必要があった
- `EW_CreditPurchaseCustomerInfo_AN` という action は存在せず 0KB で失敗
- 初回 `bank_payment_type=4` 保存を先に試みた → 「債権買取顧客情報が未登録」かつ「7日〜月末」二重エラーで失敗
- `primary_address_street` / `primary_address_street_kana` を `input` と想定 → 実際は `textarea`
- `#zipCodeBtn`（tframe用）を使用 → shimamura は `input[value="〒"]` が正しいセレクタ
- bank_code=0001（架空コード）では「銀行情報を入力してください」エラー → 0005（既存値）を使うべきだった
