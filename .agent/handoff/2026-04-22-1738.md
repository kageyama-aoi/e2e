## 試したこと・結果

### 成功したアプローチ
- `fillTextFields(I, fieldMap)` で `FORM_FILL_FAST=true` のとき `executeScript` 一括入力、`false` のとき `fillField` 個別入力に切り替え → 両環境で動作確認済み
- `#tf-message-summary` セレクタでバリデーションエラーを確実に検出 → 従来の `waitForText(lastName)` 方式では空文字や既存テキスト反応でのミス検出があったが、これで解消
- 郵便番号ボタン: `I.click('#zipCodeBtn')` + `I.wait(1)` → 都道府県・市区町村が自動入力される。番地・カナは手動入力が必要
- 銀行コード: `I.fillField('#bankCode', '0001')` + `I.wait(1)` → 銀行名が AJAX で自動入力（ポップアップは不要）。CSVに bankName/bankBranchName 列は不要
- メニュー経由遷移: `a:has-text("マスター"/"Master")` テキストベース + `a[href*="module%2Few"]` パターン組み合わせ → 日英両言語対応

### 失敗したアプローチ（理由）
- `a[title="Master"]` セレクタ → juku 環境英語HTMLに存在するが culture 環境は日本語のため、title 属性では言語対応できなかった → テキストベースに変更
- `shareiMeisaiNo` フィールド → AccountPage 作成時に HTML から抽出したが、実際のフォームには存在しなかった → 除去
- 銀行コードのポップアップ操作 → ユーザーの初期説明でポップアップがあると伝えられたが、実際はポップアップなし。`fillField` + `wait` で AJAX 補完のみ

### 重要な ENV 変数
| 変数 | 説明 |
|---|---|
| `FORM_FILL_FAST=true` | executeScript一括入力（高速・イベント非発火） |
| `USE_MENU_NAV=true` | メニュー経由遷移（URL直打ちより遅いが画面遷移を確認できる） |
| `TFRAME_LANGUAGE=en` | jukuプロファイルのみ有効。cultureは常に ja |

### よくあるエラーと対処
- `Field "#xxx" was not found` → input.html の id を再確認。フォームに存在しない列をCSVから除去する
- ID重複エラー → CSV の idnumber 値を変更して再実行
- バリデーションエラーが出てもテストがパス → `submitTframeFormAndVerify` の実装で `#tf-message-summary` をチェックしているので発生しないはず。発生した場合は submit 後の wait 時間を増やす
