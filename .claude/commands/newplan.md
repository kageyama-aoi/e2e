以下の手順で新しい開発サイクル（大きめの作業）を開始してください。作業状況は Issue に書く運用なので、計画は親 Issue に置きます（#340 で `.spec/` をやめた）。

1. やりたいことを聞き取る（背景・ゴール・やらないこと・触ってはいけない範囲）。
   - 関連しそうな既存 Issue を `gh issue list` で探し、重なるものがあれば先に伝える

2. 親 Issue を 1 件作る（`gh issue create`）：
   - 本文: 背景 / 方針 / 進め方（チェックリスト）/ 決定事項 / 関連 Issue
   - ラベル: 種別（`enhancement` / `bug` / `documentation`）＋対象（`shimamura` / `tframe` / `tooling` など）
   - 番号は「1.」や「A・B」で書き、丸数字は使わない
   - 独立して追いかけたい項目だけ子 Issue にし、親のチェックリストからリンクする

3. 完了後、以下を報告する：
   - 作った Issue の番号と URL
   - チェックリストの最初の項目（どこから始めるか）
   - 「方針や順番を直したいところがあれば教えてください」

進めている途中で決まったこと・止まった理由は、その親 Issue のコメントに書く（メモリや HANDOFF にだけ書かない）。
