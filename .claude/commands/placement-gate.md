新しいファイル・概念の配置を決定するゲートプロセスを実行してください。

## ステップ1：AGENTS.md の配置ルールを読み込む

`AGENTS.md` の「ディレクトリ配置ルール」セクションを読み込み、現在の配置ルール（置いてよいもの／置いてはいけないもの）を把握する。

## ステップ2：対象ファイル・概念の性質を分類する

ユーザーが作ろうとしているファイルについて、以下の質問に答える形で性質を明確化する：

1. **このファイルは何をするものか？** （1〜2行で）
2. **誰が使うか？**
   - テスト実行中に CodeceptJS が `require()` する → `support/` または `pages/`
   - テストシナリオそのもの → `tests/`
   - テストへの入力データ（CSV・パラメータ） → `data/`
   - ユーザーが手動で起動するツール → `run/` または `scripts/`
3. **アプリの構造・画面に関する知識を持つか？**
   - Yes（メニュー定義、URL解決、Page Object） → `pages/`
   - No → 上記の分類を継続

## ステップ3：配置先を判定する

分類結果と AGENTS.md のルールを照合し、以下のいずれかを宣言する：

### パターンA：既存カテゴリに合致
```
【配置判定】
- 性質：{分類結果}
- 配置先：{ディレクトリ}/
- 理由：{AGENTS.mdのルールのどの記述に基づくか}
→ このまま実装に進んでよい
```

### パターンB：既存カテゴリに当てはまらない（新概念）
```
【配置判定】⚠️ 新概念 — 実装前にルール確立が必要
- 性質：{分類結果}
- 最も近いカテゴリ：{ディレクトリ}（ただし完全には合致しない）
- 理由：{何が既存ルールと合わない点か}
→ AGENTS.md の配置ルール表に新しい行を追記してから実装する
```

パターンBの場合は、AGENTS.md への追記案をユーザーに提示し、承認を得てから追記・実装を進める。

## ステップ4：完了報告

配置先が確定したら以下を報告する：
- 確定した配置先
- ファイル名の命名規則（AGENTS.md の命名規則セクションに基づく）
- 次のアクション（実装開始 or AGENTS.md 更新）
